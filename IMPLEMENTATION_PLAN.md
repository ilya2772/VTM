# Implementation plan

Работа выполняется строго по одному этапу за запуск. Перед началом этапа необходимо прочитать `PRODUCT_SPEC.md`, этот файл и `STATUS.md`; после реализации — запустить указанные проверки и обновить `STATUS.md`. Следующий этап автоматически не начинается.

## Этап 1. Каркас приложения и инженерные правила

**Цель:** создать воспроизводимую основу Next.js-приложения.

**Задачи:**

- инициализировать Next.js App Router, React и TypeScript strict;
- подключить Tailwind CSS, linting, форматирование, Vitest и Playwright;
- определить структуру модулей и server/client boundaries;
- добавить базовые команды разработки, сборки и тестов;
- создать безопасный `.env.example` со всеми требуемыми переменными;
- зафиксировать правила Decimal-расчётов и запрет утечки секретов.

**Критерии готовности:**

- приложение запускается и собирается без ошибок;
- strict typecheck, lint и базовый smoke unit-test проходят;
- `.env.example` не содержит секретов;
- README содержит первичные команды запуска.

## Этап 2. Схема PostgreSQL, Prisma и seed

**Цель:** реализовать целостную модель хранения торговых и риск-данных.

**Задачи:**

- описать все требуемые модели, enum, связи, индексы и Decimal-поля Prisma;
- добавить ограничения целостности и поля идемпотентности;
- создать начальную миграцию;
- создать seed с демо-пользователем, счётом 50 000 USDT, challenge rules и инструментами;
- добавить repository/service boundaries для транзакционной работы с БД.

**Критерии готовности:**

- Prisma schema валидна;
- миграция применяется к чистой БД;
- seed повторяемо создаёт пригодный демо-аккаунт без дублей;
- денежные поля используют Decimal-compatible типы.

## Этап 3. Аутентификация и базовая защита API

**Цель:** защитить демо-аккаунт и серверные команды.

**Задачи:**

- реализовать безопасный вход и выход;
- использовать серверную сессию и HttpOnly cookie;
- добавить Zod-валидацию, CSRF-митигацию для выбранной схемы и rate limiting;
- унифицировать безопасные API-ошибки;
- добавить аудит входа и критических действий.

**Критерии готовности:**

- защищённые endpoints недоступны без сессии;
- cookie имеет корректные security-атрибуты;
- некорректные, повторные и rate-limited запросы получают ожидаемые ответы;
- секреты и чувствительные данные не попадают в клиент или логи;
- unit/integration-тесты защиты проходят.

## Этап 4. Доменная математика исполнения

**Цель:** создать чистое детерминированное ядро торговых расчётов.

**Задачи:**

- реализовать Decimal-расчёты Long/Short PnL;
- реализовать maker/taker fees, spread и slippage;
- реализовать margin и liquidation price с configurable maintenance margin;
- реализовать правила Market, Limit, Stop Limit, partial/full close, SL/TP и liquidation;
- документировать прозрачную модель simulated execution.

**Критерии готовности:**

- нет floating-point арифметики в денежных расчётах;
- граничные случаи и округление заданы явно;
- unit-тесты PnL, комиссий, spread/slippage, liquidation и SL/TP проходят;
- модель исполнения описана в README.

## Этап 5. Risk engine и жизненный цикл challenge

**Цель:** реализовать проверяемые prop challenge rules.

**Задачи:**

- рассчитывать balance, equity, realized/unrealized PnL и peak equity;
- рассчитывать daily starting equity, daily/overall drawdown и reset по timezone;
- учитывать минимальные торговые дни и profit target;
- реализовать переходы `active`, `passed`, `failed`;
- фиксировать Violation, блокировать новые ордера и опционально закрывать позиции по конфигурации.

**Критерии готовности:**

- формулы и момент дневного сброса описаны в README;
- переходы состояния детерминированы;
- тесты daily/overall drawdown, passed/failed и нарушений проходят;
- причина блокировки пригодна для показа пользователю.

## Этап 6. Market-data gateway и demo-feed

**Цель:** безопасно нормализовать исторические и real-time котировки.

**Задачи:**

- создать серверный Pyth adapter для инструментов, metadata, history и streaming;
- корректно нормализовать price/exponent, timestamp, confidence и status;
- реализовать heartbeat, stale threshold и exponential-backoff reconnect;
- реализовать серверный SSE или WebSocket endpoint без утечки API key;
- реализовать явно маркированный детерминированный demo-feed;
- агрегировать ticks в OHLC без дубликатов;
- возвращать `N/A` для неподтверждённых рыночных показателей.

**Критерии готовности:**

- ключ Pyth остаётся только на сервере и не логируется;
- UI-контракт различает live/demo/reconnecting/stale/error;
- stale price запрещает новые исполнения;
- unit-тесты stale prices и OHLC aggregation проходят;
- gateway корректно работает в demo-режиме без внешнего ключа.

## Этап 7. Транзакционный execution service и API

**Цель:** связать доменную математику, risk engine, котировки и БД.

**Задачи:**

- реализовать серверные команды создания, изменения и отмены ордеров;
- реализовать открытие, partial/full close, SL/TP и liquidation;
- проверять свежесть цены, лимиты плеча/размера и доступный баланс;
- использовать транзакции и idempotency key;
- создавать Fill, Trade, snapshots, violations и AuditLog;
- обрабатывать pending Limit/Stop Limit при поступлении котировок.

**Критерии готовности:**

- браузерские price/PnL/balance/risk values игнорируются как источник истины;
- повтор одного idempotency key не создаёт второй ордер;
- баланс не может стать отрицательным;
- integration-тесты полного жизненного цикла ордера проходят;
- атомарность подтверждена тестами ошибок и повторов.

## Этап 8. UI foundation и адаптивный shell

**Цель:** создать оригинальный, доступный каркас профессионального терминала.

**Задачи:**

- определить дизайн-токены, тёмную/светлую темы и компактную типографику;
- реализовать верхнюю панель и навигацию с активным Trade;
- реализовать desktop layout с левой, центральной и правой областями;
- реализовать tablet/mobile layout с вкладками;
- добавить доступную клавиатурную навигацию и состояния loading/empty/error;
- подключить Zustand только для необходимого клиентского UI-состояния.

**Критерии готовности:**

- композиция работает на mobile, tablet и 1440–1920 px;
- бренд и визуальные элементы самостоятельны;
- все отображённые кнопки имеют реальное действие;
- базовые accessibility и responsive проверки проходят;
- тёмная тема используется по умолчанию.

## Этап 9. График и ChartProvider

**Цель:** дать пользователю полноценный график через лицензионно корректный адаптер.

**Задачи:**

- реализовать `ChartProvider` и контракт datafeed;
- реализовать `onReady`, `searchSymbols`, `resolveSymbol`, `getBars`, `subscribeBars`, `unsubscribeBars`;
- подключить Advanced Charts только при наличии официальных файлов;
- подключить Lightweight Charts fallback с заметным ограничительным уведомлением;
- добавить все таймфреймы, типы доступных графиков, OHLC и trade markers;
- обеспечить корректную пересборку подписки и сохранение layout/drawings/settings;
- добавить fullscreen и theme integration.

**Критерии готовности:**

- все 12 таймфреймов видимы и кликабельны;
- история загружается, live candle обновляется без дублей и утечек;
- переключение symbol/timeframe не зависает;
- fallback честно обозначен и работоспособен;
- Advanced Charts не имитируется и закрытые файлы не добавлены в репозиторий.

## Этап 10. Order ticket и подтверждение

**Цель:** реализовать безопасный пользовательский поток выставления ордера.

**Задачи:**

- реализовать Limit/Market/Stop Limit и Buy/Long/Sell/Short;
- добавить размер в USD/asset units, leverage и быстрые проценты;
- добавить SL, TP и серверный preview;
- показывать fee, expected execution, liquidation, risk/reward, potential P/L;
- добавить обязательный confirmation dialog и идемпотентную отправку;
- показать simulated execution, stale/risk/error states.

**Критерии готовности:**

- все поля валидируются на клиенте для UX и повторно на сервере;
- submit невозможен при stale price или нарушенном risk limit;
- двойное нажатие не создаёт дубль;
- успешные и ошибочные исходы понятны пользователю;
- component/integration-тесты формы проходят.

## Этап 11. Панели challenge, позиций, ордеров и риска

**Цель:** сделать состояние счёта и торговли полностью наблюдаемым и управляемым.

**Задачи:**

- реализовать challenge metrics, прогресс, статистику и последние сделки слева;
- реализовать Positions, Orders, History и Risk справа;
- добавить live mark price и unrealized PnL;
- добавить edit SL/TP, cancel order, partial/full close;
- показать Daily Drawdown, оставшийся лимит и объяснения нарушений;
- корректно отобразить `N/A`, demo badge и connection states.

**Критерии готовности:**

- все требуемые метрики отображаются из серверного источника истины;
- действия действительно изменяют серверное состояние;
- live PnL обновляется без перезагрузки;
- risk violation заметен и объяснён;
- UI-тесты ключевых действий проходят.
